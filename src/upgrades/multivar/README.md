# Multivariate covariate analysis of real-task learnability (Reviewer 1, comment 1)

> "Please provide a multivariate regression analysis on the real-world datasets controlling for sequence
> length, GC content variance, and homology redundancy to explain what unobserved factors drive
> performance deviations, addressing the exceptionally low goodness-of-fit and high fitting uncertainty
> observed on real tasks despite the strong synthetic dose-response."

Tasks are the units of analysis. The primary set is the 11 TF-motif tasks, the Route-1 scope (`S11`); the secondary set is all 15 tasks (`S15`). The primary outcome is Table-1 benchmark MCC (best-k LightGBM); AUROC is secondary. The analysis plan and the decision rule are in the docstring of `run_multivar.py` (first 99 lines), frozen on 2026-09-23 21:44 before any new covariate was computed; a verbatim copy with its sha256 is in `results/upgrades/multivar_preregistration.txt`, and `tests/test_multivar.py` checks the hash on every run. Everything added later is labelled POST HOC: P1–P4 (first run), P5–P11 (first verification round, 2026-09-24), P12 and the fix-round-2 columns (second verification round, 2026-09-24 evening), P13 and the fix-round-3 columns (third verification round, 2026-09-24 night). CPU-only, torch-free. Seed 42, 1000 task-bootstrap resamples (percentile CIs, task = unit), 1000 permutations.

## Data integrity and provenance
- **GB tasks** are read from private copies of the Zenodo cloud-cache zips (`external/multivar/gb_zips/`, record 16605299). `_mv._read_gb_zip` replicates `data.load_dataset`; the shared loader is not used because `genomic_benchmarks.download_dataset` deletes and re-extracts the task directory on every call (see the `_mv.py` docstring). **NT tasks** go through `data.load_dataset` (pinned HF revision).
- **Count checks:** every load (`_mv.load_task_cached`) asserts n_train/n_test equal Table 1. Four sequence-cache pickles (`demo_human_or_worm`, `human_ensembl_regulatory`, `human_nontata_promoters`, `demo_coding_vs_intergenomic_seqs`) date from 2026-09-23 21:58–22:00, before the 22:15 data-integrity cutoff; they are kept because this count assertion runs on every load, and the downstream values they feed reproduce published numbers (composition-only baseline |diff| = 0; `dedup_eval.py` reproduces Table-1 MCC).
- **Composition-only baseline** reproduces the 5 published `composition_clean*` values exactly (`multivar_comp_reproduction.csv`).
- **Threads:** the 15 composition-only checkpoints (2026-09-24 11:13–11:20) and the 4 cached dedup predictions (12:27–12:57) were computed with LightGBM `num_threads=3`, before the 2-thread rule; the code now uses 2. Both reproduce published values exactly, so they were kept.
- **Homology method:** identical to `homology/measure_homology.py` (imported); sparse per-row max and a 20k-sequence chunked train split with a running max are checked against the dense reference by a unit test. `nt_promoter_tata` reproduces `homology_leakage.csv` exactly. Five tasks with more than 1e9 test×train pairs use a pre-registered uniform sample of 5,000 **test** sequences against the **full** train split, with Wilson CIs. The verbatim-duplicate audit (step 5) uses the full test split.
- **Fix round 3 (2026-09-24 night), all post hoc, plan and hash unchanged:** (i) every Spearman permutation p of a task set with n ≤ 12 is exact, by dynamic programming over all n! orderings (`exact_rank_perm_p`; checked against brute-force enumeration with and without ties; S11: 0.012774, previously Monte Carlo 0.01298). (ii) A degenerate |ρ| = 1 partial gets no percentile CI (NaN) as well as no p. (iii) P5 and P12 report GC mean's own Spearman with MCC (exact p) next to discriminability's, the paired task-bootstrap CI of the difference, which of disc-only / GC-only has the lower LOTO MAE, the single tasks whose removal reverses that ordering, both MAEs without the 3-class regulatory task, and that task's own LOTO errors (`gc_disc_readout`). (iv) P5 adds all 330 seven-task subsets of S11 (`multivar_posthoc_subsets7.csv`). (v) P12 uses exact-duplicate terminology: `dupfree9_*` = exact duplicates and the exact union collapsed; `noshare8_*` = no exact sequence sharing ≥ 0.1% (the largest remaining pair shares 13 sequences, 0.011%); columns `n_exact_distinct_sets`, `n_no_exact_sharing` (maximum set of tasks without exact sharing); `n_distinct_sets` no longer miscounts a set holding `nt_promoter_all` with only one of its components; two regulatory-removed rows. (vi) P13: locus-level sharing (`audit_locus_overlap.py`); tasks with a locus link ≥ 0.50 / 0.25 / 0.10 (thresholds fixed before P13 ran) are treated as non-independent and the correlations are recomputed on every maximum set of mutually unlinked tasks (`multivar_posthoc_locus_independent.csv`). (vii) `write_interpretation.py`: every 'discriminability beats GC' statement is guarded by the regulatory-removed ordering; the word 'flip' is not used; Table II gets a GC-mean column; the Real-task paragraph is rewritten.
- **Fix round 2 (2026-09-24 late evening), all post hoc, plan and hash unchanged:** (i) Spearman p-values at n ≤ 9 are exact permutation p over all n! orderings (`perm_spearman_p`; Monte Carlo 200,000 orderings for n = 10–11), reported next to scipy's t-approximation, which understates p at small n (paper's 9: 0.0025 vs exact 0.0045). (ii) A degenerate |ρ| = 1 (Spearman or partial) gets p = NaN, reported as "degenerate"/"undefined", never p = 0. (iii) Partial Spearman at small n also gets a residual-permutation p (`perm_partial_p`). (iv) A1 gains Holm-adjusted p (`posthoc_partial_p_holm`) and the reverse partial's valid-resample count (`posthoc_rev_n_boot_ok`). (v) `homology_clean` flags in P5/P12; `write_interpretation.py` asserts that only a task set with no task ≥ 0.05 is ever labelled homology-clean (the n = 8 set, which keeps `nt_enhancers_types`, is not). (vi) P11 records that the family label equals Table I's 'solved' split (parsed read-only from `bibm/paper_bibm_submitted.tex`) and is a dichotomy of MCC. (vii) P12 recomputes the headline statistics on distinct and sequence-disjoint task sets. (viii) `dedup_eval.py` tolerance 5e-4 → 5e-5; `audit_exact_dups.py` adds an any-copy label-concordance column.

## Result (numbers and file citations in `multivar_interpretation.txt`)
- **Pre-registered decision rule: NO.** No covariate set improves on discriminability out of sample (nested LOTO MAE 0.143 vs 0.140, ΔMAE +0.003 [−0.051, +0.066]; incremental permutation p = 0.43). The nested search picked a GC-mean model in 11/11 folds and a discriminability model in 0/11. GC-only alone has LOTO MAE 0.086, but it is the in-sample AICc winner, so that number is not selection-honest; inside the folds the search added a second covariate in 5/11 folds and was worse than GC-only in 4 of them.
- **The reviewer's model (disc + length + GC SD + homology) overfits:** LOTO MAE 0.233 vs 0.140 on S11, where no coefficient's CI excludes 0. On S15, disc is the only term whose bootstrap CI excludes 0; length's t-CI [−1.07, −0.03] excludes 0 but its bootstrap CI does not.
- **Homology does not confound the cross-task relation** (ρ(disc, MCC | homology) +0.74 [+0.29, +0.99]). Partial ρ given each covariate: CI excludes 0 for 5/10; t p < 0.05 for 7/10 uncorrected, 1/10 after Holm.
- **The real-task MCCs form two clusters.** The post-hoc promoter/enhancer label is exactly Table I's 'solved' vs failing split (MCC 0.846–0.907 vs 0.398–0.593), so its LOTO MAE of 0.042 is close to tautological: the regression carries essentially one between-cluster contrast. Discriminability is collinear with GC content (ρ +0.69) and both separate the clusters. GC content tracks MCC at least as closely as discriminability (Spearman +0.86 vs +0.74 on S11; difference CI [−0.32, +0.53]), has the lower LOTO MAE on all 11 tasks (0.086, an in-sample-chosen model) and survives control for disc. Of 17 task sets, disc has an MAE lower by > 0.005 only on the 3 homology-clean sets that contain the 3-class regulatory task (clean 7: 0.039 vs 0.123; without that task 0.040 vs 0.034; its GC mean pools three classes) and on the GB-only suite. Within clusters (≤ 5 exact-duplicate-free datasets) neither is resolvable. Real tasks cannot isolate discriminability; only the synthetic dose-response does.
- **Measurement noise is not the problem:** test-set sampling noise is 1.5% of the misfit.
- **The paper's 'homology-clean' 9 are not clean:** they include `human_enhancers_ensembl` (38.0% of test sequences are verbatim train copies) and `nt_enhancers_types` (25%, all of class 2). The only homology-clean set is n = 7 (every task < 5% near-duplicates): ρ = +1.00, exact p = 0.0004. The n = 8 set (+0.93, exact p = 0.0022) keeps `nt_enhancers_types` and is a sensitivity row only.
- **The 11 tasks are not 11 independent units.** Exactly, they are 9 exact-duplicate-free sequence sets (at most 8 without exact sharing): `nt_promoter_all` is exactly the union of the TATA and no-TATA tasks, `nt_enhancers_types` relabels `nt_enhancers`, and the OCR class of `human_ensembl_regulatory` is, as a multiset, `human_ocr_ensembl`'s positive class (69,902 = 69,902 train, 17,476 = 17,476 test). At the locus level (31-mer audit) the promoter tasks of both suites and the regulatory task's promoter class share most loci (72.7% of `human_nontata_promoters` positives are mostly contained in `nt_promoter_all`); the enhancer tasks share little (12–15% with the regulatory task, near their own negatives' 6–9%). With exact duplicates collapsed, disc's ρ is +0.79 to +0.82 (n = 8–9, exact p ≤ 0.028) and GC's +0.83 to +0.95; on the largest sets of tasks sharing no loci (n = 7, 2 solved tasks each) disc's ρ is +0.71 to +0.82 (exact p 0.034–0.088) and GC's +0.93 (p = 0.0067). The paper's NT-only row (n = 5) rests on 3 exact-duplicate-free sets.
- **Largest deviation (post hoc):** `nt_enhancers_types`' discriminability was read from its non-enhancer class (TBP, the TATA contamination axis). Under a uniform functional-class rule, LOTO R² is +0.65 [+0.20, +0.82]; the pre-registered +0.44 stays primary.
